# Worklog

The running per-change history. One line per landed change, newest first, appended **in the same
commit as the change** (`.agents/rules/documentation.md` → the same-change update contract).
`scripts/check-docs.sh` fails any commit that changes code but not this file, so the line is the one
mechanically-enforced part of that contract.

A `CHANGELOG.md` would supersede this file — the gate resolves `CHANGELOG.md` first. This repo has
none, so this is the worklog target.

- 2026-10-06 — **M6 and M7 shipped** (released as `v0.5.0`): **search**, backed by a real index. `src/domain/search-query.js` tokenizes (splitting camelCase, so "shotList" indexes as "shot"+"list") and parses queries into required terms, `-excluded` terms and quoted phrases; matching is whole-token, so "cat" does not match "concatenate". `src/application/build-index.js` walks the drives in two passes — metadata for everything, contents only for text/code/PDF/Office under a size cap — so search is useful from the first second rather than after an hour. `src/domain/index-rules.js` refuses `node_modules`, `C:\Windows` and the Recycle Bin, and survives an unreadable folder instead of ending the scan. - 2026-10-06 — **The native tells: real file icons, type-ahead, collision resolution** (released as `v0.19.0`): P3 of the audit plan. Every row now shows the **OS's own file-type icon** instead of one generic page glyph, and the two rules that make it affordable are asserted by tests that **count calls** rather than measure time: the cache key is the EXTENSION rather than the path, so a folder of 5,000 videos costs ONE shell lookup, and ten simultaneous requests for one type **share a single in-flight call** — the case a naive cache misses, because a listing paints its rows together and all of them ask before any answer returns. Nothing waits for it either: the listing paints immediately with its vector glyph and swaps in the real icon when the shell answers, repainting **once for all of them** rather than once per file, which keeps the scroll position. `getFileIcon` reads the NAME and the association, so a cloud placeholder is never hydrated. **Type-ahead** (typing a letter jumps to the first match, more letters narrow, the same letter cycles) with a 900ms buffer, because a buffer that never expires turns every stray keystroke into a search for a 12-letter word. **A name collision is now a question rather than a wall**: copying onto an existing name used to just fail, and it now asks BEFORE the transfer runs rather than after it fails — the old order cost the user the whole operation to learn something the app could have asked up front. Skip / Keep both / Cancel, asked only when something actually collides, remembered for the session. **There is deliberately no "Replace"** — overwriting is the one action here that destroys data, and offering it in a dialog reached by pasting would make it the fastest way to lose a file; that needs the owner's decision, not my initiative. Wiring `suggestUniqueName` up (it had been written, tested and unused since long before this branch) found a real bug in it: it produced **`Take 1.mp4 2`**, whose extension had become `.mp4 2`, so the file stopped being a video to every other program; Explorer's `Take 1 2.mp4` is what it does now, and a leading dot counts as part of a name so `.gitignore` numbers to `.gitignore 2`. **Hidden files**: `isHidden` had been computed for every item since the bulk reader landed and nothing read it — a hidden file never shown is the same as one that does not exist. `Ctrl+Shift+H` and a View entry, off by default, the entry carrying a checkmark so it states the setting rather than only offering to change it. **The window remembers its size and position**, including the part that is easy to get wrong: a saved position is coordinates on a display that may no longer exist, and a window restored onto an unplugged monitor opens off screen, which is indistinguishable from the app failing to launch — so the bounds are validated against the displays that exist now, while a window deliberately hanging off an edge is still restored. Two defects the new checks found in the wiring rather than in the app: a `const` emitted **inside** an object literal in the preview harness (a syntax error that stopped the whole app rendering), and `MENUS` being a module constant, so a label that depends on state is **frozen at load** and the checkmark could never appear — labels may now be functions, resolved at open time.

Fixed with the missing gutter cell; both now at 226. Size and date are **right-aligned** so digits line up — tabular figures were already set, and left-aligning threw that away. **Five tokens were referenced and never defined** (`--accent-soft`, `--bg-soft`, `--hover`, `--line-soft`, `--fg-dim`), so ten `var(--x, fallback)` sites rendered a fallback chosen for a dark background; in light mode tag hover came out at **1.00:1**, a hover state that was invisible. **Disabled controls disappeared** — `opacity: .45` measured 2.01:1, under the 3:1 floor, and degraded the text as well as the icon; replaced with a real color at 3.81:1 that still reads as disabled. **One icon stroke width instead of four** (1.1/1.2/1.3/1.4 at a single 16px size — the audit said seven widths and four sizes; the source says four and one). **The empty state is centered** rather than a 14px caption in the corner. Two of the audit's own numbers did not survive contact: the muted-text token's binding constraint was not white but the search field (`rgba(0,0,0,0.043)` over the toolbar tint → `#f0f0f2`), where it measured **4.45:1** — a fail by 0.05, now tuned against that worst surface; and "focus invisible on nine classes" was really invisible on *selected* rows only, because the ring color was the selection background. **The measuring itself needed fixing**: the first contrast probe fed 0-255 channels to the sRGB transfer function, which expects 0-1, and reported a near-black label on white as **174:1**; the wrong values looked reasonable (mid-grays read 7.17 instead of 5.07) and only the impossible number gave it away, so the check now asserts a plausible range as well as a passing ratio.
- 2026-10-06 — **Reachable by keyboard, and spoken out loud** (released as `v0.17.0`): P1 of the audit plan, plus the **Electron 44** upgrade the owner asked for (`electron` ^44.7.0 and `electron-builder` ^24.13.3 → ^26.15.3, because builder 24 predates Electron 44 and cannot package it; the upgrade is for file-clipboard interop with Explorer, electron#51707). The keyboard was unusable in one specific way: `document.addEventListener('keydown')` owns Enter and Space and `preventDefault()`s both, so tabbing to **any** button — toolbar, sidebar, a dialog's own Cancel — and pressing Enter or Space did **nothing**, and Space was worse because it is the global Quick Look key. A focused button now owns both, checked before every other branch, because it is a rule about who owns the key rather than one command among many. **Tab could not reach the files at all**: rows were `role="option"` with no `tabIndex` and only search results were focusable, so every shortcut in the app was theoretical. The list is now a `listbox` with a single tab stop on the **active** column and arrows moving within it — the first attempt keyed the tab stop off `column.selectedName` and made all three columns tab stops, because column view holds a selection in several columns at once, caught by the new check. **The app was silent**: two live regions (`role="status"` for counts, `role="alert"` for errors), both `sr-only` — clipped rather than `display: none`, which would remove them from the accessibility tree — carrying selection ("…mp4, file, 1 of 12"), toasts and read failures, deliberately a short sentence rather than the status bar verbatim and guarded against repeating itself. **Arrows now move real focus**, because selection and focus are the same thing in a listbox and a screen reader was reading the toolbar while the highlight walked the list. **Ctrl+A then Delete used to bin the whole folder silently**; anything whose consequences cannot be judged from the screen now asks first (more than one item, or a folder even alone), the dialog names the count ("Move 12 items to the Recycle Bin?") rather than asking a vague "are you sure", and focus starts on **Cancel** — while a single file is still deleted with no dialog, since confirming the normal case every time is its own kind of unusable. **Contrast**: `--fg-muted` was `#7a7a7f` at **4.27:1 on white**, under the WCAG AA 4.5:1 minimum, and that one token paints ten surfaces; now `#6e6e73`, measured 5.07:1 on white and 4.74:1 on the sidebar tint. The focus ring was invisible on a selected row (1.00:1) because the ring color *was* the selection background; it is drawn in `currentColor` now, so it resolves to the row's own text color — near-black normally, white when selected, 5.27:1 against the selection.
- 2026-10-06 — **P0 honesty, first batch** (released as `v0.16.0`): the mapped-network-drive delete, which was the worst outcome the app could produce — a **permanent delete reported as a recoverable one**. `shell.trashItem` does not fail on a mapped drive (`Z:` pointing at a share); it deletes permanently and reports success, and the app then said "moved to the Recycle Bin". A UNC path was already refused for this reason but a mapped drive was not, because its path looks local — and the old rule's own comment admitted it "cannot be told apart from a real drive by their path alone". It can: the drives adapter already reads `DriveType` and already labels `DriveType === 4` as `network`, and nothing consulted it. `isNetworkDrivePath` (domain, pure, takes the roots) plus a refuse branch in the trash use case, fed by the drive list from the composition root. The lookup is **best-effort by design** — if the drive list cannot be read the path falls back to the UNC-only rule rather than blocking a legitimate delete, because a guard that fails closed on a file manager is a worse bug than the one it fixes. Three smaller honesty defects of the same shape (the app said something untrue): a failed search reported **"Nothing matches"** because `state.searchError` was written three times and never rendered; **"Empty" was printed under a permission-denied banner**, two contradictions stacked; and the **folder right-click menu omitted "Move to Recycle Bin"** while the File menu and Delete key both offered it — its comment claimed the app "has no recursive delete yet", which is false (the Recycle Bin does recursion natively).
- 2026-10-06 — **Quick Look arrows, a visible Quick Look button, and a real shortcut sheet shipped** (released as `v0.15.0`): all three were discoverability failures, not missing features. The Quick Look overlay was a header and a body with no arrows, no counter and no visible close — the arrow *keys* worked, which is how the view was found at all (by accidentally pressing space). It now has steppers and a "3 of 12" counter that walk **every file, not only media**, which is the deliberate difference from the preview pane's media-only arrows: Quick Look is the "look at this" view, so the right arrow should always move rather than stop dead on a text file. A toolbar button makes the view reachable without the key. The shortcut sheet was a flat seventeen-row list missing **Copy, Cut, Paste, Select All and Refresh**; it is now four groups across two columns with every key drawn as a keycap, complete, and reachable by `Ctrl+/`. Five defects found by measuring rather than looking: (1) **the toolbar title was never centered** — the rule's own comment claimed two `flex: 1` groups center it, but a flex item will not shrink below its content so the wider right group won; 39.5px off, then 72px once another control was added, now 1px off at both 1180px and 900px via a `minmax(0, 1fr)` three-column grid; (2) **`.modal-card-wide` had never applied** because it was declared before `.modal-card` and equal specificity means the later rule wins — the sheet rendered 340px wide and ran off the bottom of the window; (3) **a percentage `max-width` on a grid item collapses**, clipping the folder name to 18px; (4) **hit targets under 32px** (steppers 26x24, toolbar buttons 28x26); (5) **a toggle branch that could never run**, because the Quick Look overlay covers the window and its own toolbar button cannot be clicked while it is open — deleted rather than left dead. Every one now has a regression check that measures geometry rather than asserting a class name.
- 2026-10-06 — **Drag and drop shipped** (released as `v0.14.0`): dragging a file onto a folder now moves it, Ctrl copies, and files can be dropped in from Explorer. There were ZERO drag handlers before this — the reported bug. `test/drop-files.test.js` pins the rules that lose data: a folder can never be dropped into its own subtree (reached from the other side than the transfer rules catch), a collision is refused, a partial failure says so, and putting an item back where it came from is a quiet no-op. **Drag-out is deliberately excluded:** `webContents.startDrag` on Windows makes the app refuse to be its own drop target (electron#7118), so native drag-out and in-app drop targets are mutually exclusive without a native module; the in-app half is the one that supports multi-select and Ctrl, so it landed first and the `startDrag` wiring was removed rather than left dead. The absolute path now travels on the item from the reader, because `dragstart` is synchronous and cannot await IPC. Two bugs found: a duplicate `join-path` handler built on Node's host-dependent `path.join` shadowed the domain-layer one (caught by the composition-root test within a minute), and a JS backslash literal nested inside a shell-quoted Python string broke the preview build twice.
- 2026-10-06 — **M6 shipped** (released as `v0.13.0`): **native bulk enumeration**, so a folder is read in ONE call instead of one call per file. The old reader spawned PowerShell for attribute flags (which Node's `fs.Stats` does not expose at all) and then paid an `lstat` per entry on top of it. The same call now returns size, times and the directory flag too: **1 process spawn + N stat calls → 1 process spawn**. The per-entry route remains as the fallback for non-Windows, PowerShell unavailable, or a failed call, so the reader is correct everywhere and fast only on Windows. The claim is verified by COUNTING CALLS, not by timing: a fake filesystem with 5,000 entries records **0 stat calls** on the fast path (`test/directory-reader-perf.test.js`), because a wall-clock assertion would be flaky on a busy CI box. Times cross the boundary as raw .NET ticks rather than formatted dates — a formatted date's format depends on the machine's culture, and ticks are an integer that cannot be misread. The filename is emitted LAST so a name containing a tab survives (Windows permits a tab, and forbids only newline and control characters). Two bugs found by writing the tests: a naive ticks conversion using `Number` instead of `BigInt` loses precision for pre-1970 dates, and a test helper that restored `process.platform` before the read silently sent every read down the fallback path — the same class of error as the bug the feature fixes.
